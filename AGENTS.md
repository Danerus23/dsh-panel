# DSH Panel — правила работы в этом репозитории

Файл для человека и для ИИ-агента, который откроет репозиторий впервые. Читается за минуту,
экономит часы: здесь описано, чего нельзя делать, как проверять изменения, где что лежит и что
уже сделано. Репозиторий публичный: <https://github.com/Danerus23/dsh-panel>.

## Что это

Панель управления локальным сервером **DeepSeek Harness** для Windows: C# / WinForms / .NET 8,
один исполняемый файл `DshTray.exe` в трее. Панель запускает и останавливает сервер `dsh web`,
следит за тарифом и балансом, делает резервные копии данных DSH и восстанавливает их, обновляет
себя с GitHub Releases. Интерфейс на трёх языках, установщик несёт внутри среду .NET Desktop
Runtime 8, лицензия MIT, автор — `Danerus23`.

## Красные линии (нарушать нельзя)

1. **Живой сервер и живая панель.** На машине владельца работает сервер DSH на порту **3080** и
   панель в трее. Их нельзя останавливать, а порт 3080 нельзя занимать своими проверками. Через
   этот сервер идёт сессия самого агента: остановишь — оборвётся ответ.
2. **Любая проверка — в изоляции.** Запускать панель из командной строки можно только с
   изолированными каталогами, иначе она прочитает и перезапишет настоящие данные:
   `DSH_PANEL_DATA`, `DSH_PANEL_STATE`, `DSH_PANEL_SSH_DIR`, `DSH_TRAY_BACKUP`, `DSH_PANEL_NO_MIGRATE=1`.
3. **`DshTray.exe` без аргументов — это GUI.** Запускать его без аргументов можно только человеку.
4. **Накат копии** (`--restore`) не запускать без `--from` с путём к копии, без изоляции и без
   свободного порта. Полную копию (`--backup --full`) на настоящем профиле не делать: она занимает
   сотни мегабайт и минуты.
5. **Личные данные не попадают в репозиторий.** Пути владельца, имена машин, логи, `settings.json`,
   `web-url.txt` (в нём токен входа), содержимое `~/.dsh` и снимки с балансом — только в
   `.gitignore`. Перед коммитом запускай `tools\check-personal.ps1`.
6. **Выпуски не переписываем задним числом.** Тег вида `v1.20.2` обязан совпадать с `<Version>` в
   `DshTray.csproj`: это проверяет CI и отказывается собирать выпуск. Если тег попал на неверный
   коммит, удали и тег, и выпуск, и поставь заново (см. «Выпуск»).

## Как проверять изменения

Полный конвейер (сборка панели, установщик, все проверки, файлы выпуска):

```powershell
cd <папка репозитория>
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\make-release.ps1
```

Отдельные проверки — все они есть и запускаются сами в конвейере:

| Проверка | Что смотрит |
|---|---|
| `tools\acceptance.ps1` | 19 приёмочных проверок панели «как чужой» на изолированном профиле |
| `tools\check-installed.ps1` | установленная панель: удаление, «Программы и компоненты», словари, вёрстка |
| `tools\check-restore.ps1` | копии и накат: что возвращается, что нет, предохранительная копия |
| `tools\check-update.ps1` | путь обновления на локальной заглушке GitHub: суммы, распаковка, сценарий |
| `tools\check-update-apply.ps1` | **сама замена файлов** в папке с пробелом (см. урок ниже) |
| `tools\check-onboarding.ps1` | мастер первой настройки открывается одним окном |
| `tools\check-lang.mjs` | словари: три языка, одинаковый набор ключей, без пустых значений |
| `tools\check-encoding.ps1` | `.ps1` и `.iss` — UTF-8 **с BOM** и переводы строк CRLF |
| `tools\check-personal.ps1` | личные данные сборщика в файлах, которые уедут в репозиторий |

Проверка в чистой Windows — отдельный стенд рядом с репозиторием (`..\dsh-deploy\test-stand`):
сборка раздатки (`prepare-panel-payload.ps1`), запуск в Hyper-V (`use-payload-iso.ps1`,
`repair-vm-iso.ps1`) и сборщик отчёта `СОБРАТЬ-ОТЧЁТ.cmd`.

## Грабли, на которые уже наступали

- **Пробел и хвостовой `\` в пути установки ломают обновление.** Панель ставится в
  `%LOCALAPPDATA%\Programs\DSH Panel`, и этот путь однажды ушёл в сценарий замены как
  `"…\DSH Panel\"`: командная строка съела закрывающую кавычку, robocopy получил ключи `/E /NFL`
  как часть пути и отказался копировать (ошибка 123). Сценарий откатился, панель поднялась прежней
  версии. Теперь хвостовые разделители срезает `UpdateService.SafePath`, а весь путь целиком
  проверяет `tools\check-update-apply.ps1`. **Правило: проверки путей делай на пути с пробелом.**
- **После `git init` версия exe становится `1.20.2+<хеш коммита>`.** .NET вписывает хеш в
  `ProductVersion`, поэтому любые сравнения версий (инструменты и сам апдейтер) обязаны брать
  числовую часть: `(... -split '\+')[0]`. Панель это делает (`UpdateService.Clean`) — инструменты тоже.
- **`.ps1` и `.iss` требуют BOM.** Инструменты правки (`edit`, `write`) BOM снимают, и PowerShell
  5.1 после этого ломает кириллицу. После правки прогоняй `tools\check-encoding.ps1 -Fix`.
- **Не перезаписывай ISO, на который смотрит виртуальная машина.** Hyper-V выдаёт права на файл в
  момент подключения привода; после подмены файла ВМ не запускается с «Отказано в доступе».
  Раздатка всегда собирается под новым именем.
- **Снимки для README снимаются на нейтральном профиле.** Рецепт: `DSH_TRAY_NODE` и `DSH_TRAY_BIN`
  ведут в `C:\Users\Public\DshPanelDemo\node\...`, `DSH_PANEL_SSH_DIR` — в ту же демонстрационную
  папку, `DSH_TRAY_BACKUP` — в её `backups` с **обезличенной** демо-копией, `language` в настройках —
  `auto`, порт — заведомо свободный (например 3095), `DSH_HOME` — свой пустой. Тогда в кадр не
  попадут ни имя владельца, ни имя машины, ни баланс, ни чужой порт. Панель рисует снимки сама:
  `DshTray.exe --shot <папка>\panel.png` (рядом с картинкой кладётся отчёт `--out`). Помни:
  `DrawToBitmap` не рисует текст выпадающих списков, поэтому мастер на снимке выглядит с пустым
  полем языка — это артефакт съёмки, а не ошибка; поэтому шаг мастера в таблицу README не выносим.
- **Установка поверх работающей панели**: панель живёт в трее, поэтому у установщика указан мьютекс
  (`AppMutex=Local\DshTray.SingleInstance`). В тихом режиме (`/SILENT`) Inno не закрывает приложение
  сам и падает с кодом 1 — сначала сними панель (`Stop-Process`), сервер при этом останется жив.
- **После мастера панель перезапускает себя** (`TrayHost.RestartSelf`): панель, которая ставила Node
  и движок, несёт окружение до установки, и сервер с первого раза не поднимается.

## Как работает обновление панели

1. Панель спрашивает `releases/latest` репозитория (`UpdateService.Repository`; подменить адрес для
   проверки можно через `DSH_PANEL_API`).
2. `--update-check` только сообщает, что есть новее; `--update-prepare [--force]` скачивает архив,
   сверяет `SHA256SUMS.txt`, распаковывает в `<состояние>\update\<версия>`, проверяет версию внутри
   и **печатает готовую команду замены** — её видно и можно запустить руками.
3. Команда запускает `update.cmd`: он ждёт выхода панели по её PID, копирует файлы robocopy, при
   ошибке откатывается на копию прежней версии и в любом случае запускает панель заново.
4. Весь этот путь целиком проверяет `tools\check-update-apply.ps1`.

## Выпуск

```powershell
# 1. поднять версию и описать изменения:
#    DshTray.csproj: <Version>1.20.3</Version>;  CHANGELOG.md: раздел «## 1.20.3 — <дата>»
# 2. прогнать конвейер и убедиться, что всё зелёное
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\make-release.ps1
# 3. закоммитить, поставить тег и отправить его — дальше работает CI
git add -A; git commit -m "..."; git push origin main
git tag -a v1.20.3 -m "DSH Panel 1.20.3"; git push origin v1.20.3
```

CI (`.github/workflows/build.yml`) собирает панель, оба архива, установщик, контрольные суммы и
заметки из CHANGELOG, затем создаёт выпуск с четырьмя файлами: `dsh-panel-setup.exe`, `DshPanel.zip`,
`DshPanel-selfcontained.zip`, `SHA256SUMS.txt`. Экшены закреплены по SHA коммита; проверить
актуальность: `gh api repos/<owner>/<repo>/commits/<tag> --jq .sha`.

Проверить уже опубликованный выпуск (скачает ассеты, сверит суммы и версии):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\Harness\_build\verify-release.ps1 -Tag v1.20.3
```

## Донаты

Донаты идут через lava.top: ссылка лежит в `AppLinks.DonateUrl`, и пока она пуста, строки
«Поддержать проект» в «О панели» нет. Та же ссылка есть в разделе о поддержке во всех трёх README.
Меняешь ссылку — поправь в `AppLinks.cs` и в трёх README сразу.
