# DSH Panel — правила работы в этом репозитории

Файл для человека и для ИИ-агента, который откроет репозиторий впервые. Читается за минуту,
экономит часы: здесь описано, чего нельзя делать, как проверять изменения и где что лежит.

## Что это

Панель управления локальным сервером **DeepSeek Harness** для Windows: C# / WinForms / .NET 8,
один исполняемый файл `DshTray.exe` в трее. Панель запускает и останавливает сервер `dsh web`,
следит за тарифом и балансом, делает резервные копии данных DSH и восстанавливает их.

## Красные линии (нарушать нельзя)

1. **Живой сервер и живая панель.** На машине владельца работает сервер DSH на порту **3080** и
   панель в трее. Их нельзя останавливать, а порт 3080 нельзя занимать своими проверками.
2. **Любая проверка — в изоляции.** Запускать панель из командной строки можно только с
   изолированными каталогами, иначе она прочитает и перезапишет настоящие данные:
   `DSH_PANEL_DATA`, `DSH_PANEL_STATE`, `DSH_PANEL_SSH_DIR`, `DSH_TRAY_BACKUP`, `DSH_PANEL_NO_MIGRATE=1`.
3. **`DshTray.exe` без аргументов — это GUI.** Запускать его без аргументов можно только человеку.
4. **Накат копии** (`--restore`) не запускать без `--from` с путём к копии, без изоляции и без
   свободного порта. Полную копию (`--backup --full`) на настоящем профиле не делать: она занимает
   сотни мегабайт и минуты.
5. **Личные данные не попадают в репозиторий.** Пути владельца, имена машин, логи, `settings.json`,
   `web-url.txt` (в нём токен входа), содержимое `~/.dsh` и скриншоты с балансом — только в
   `.gitignore`. Перед коммитом проверяй, что нового не попало.

## Как проверять изменения

Полный конвейер (сборка панели, установщик, все проверки, выпуск):

```powershell
cd <папка репозитория>
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\make-release.ps1
```

Отдельные проверки — все они есть и запускаются сами в конвейере:

| Проверка | Что смотрит |
|---|---|
| `tools\acceptance.ps1` | 19 приёмочных проверок панели «как чужой» на изолированном профиле |
| `tools\check-installed.ps1` | установленная панель: удаление, «Программы и компоненты», словари, вёрстка |
| `tools\check-restore.ps1` | копии и накат: что возвращается, что нет, предохранительная копия |
| `tools\check-update.ps1` | путь обновления на локальной заглушке GitHub: суммы, распаковка, сценарий замены |
| `tools\check-onboarding.ps1` | мастер первой настройки открывается одним окном |
| `tools\check-lang.mjs` | словари: три языка, одинаковый набор ключей, без пустых значений |
| `tools\check-encoding.ps1` | `.ps1` и `.iss` — UTF-8 **с BOM** и переводы строк CRLF |

Проверка в чистой Windows — отдельный стенд рядом с репозиторием (`..\dsh-deploy\test-stand`)
(сборка раздатки, запуск в Hyper-V, сборщик отчёта `СОБРАТЬ-ОТЧЁТ.cmd`).

## Грабли, на которые уже наступали

- **После `git init` версия exe становится `1.20.0+хеш`.** .NET вписывает в `ProductVersion` хеш
  коммита, поэтому любые сравнения версий (инструменты и сам апдейтер) обязаны брать только
  числовую часть: `(... -split '\+')[0]`. Панель это уже делает (`UpdateService.Clean`), а вот
  `tools\check-update.ps1` из-за этого падал на «новая панель распакована в папку обновления».
- **`.ps1` и `.iss` требуют BOM.** Инструменты правки (`edit`, `write`) BOM снимают, и PowerShell 5.1
  после этого ломает кириллицу. После правки прогоняй `tools\check-encoding.ps1 -Fix`.
- **Не перезаписывай ISO, на который смотрит виртуальная машина.** Hyper-V выдаёт права на файл в
  момент подключения привода; после подмены файла ВМ не запускается с «Отказано в доступе».
  Поэтому раздатка всегда собирается под новым именем.
- **Скриншоты для README снимаются на чистом профиле** (`--shot`), иначе в кадр попадут пути и баланс.
- **Установка поверх работающей панели**: панель живёт в трее, поэтому у установщика указан мьютекс
  (`AppMutex=Local\DshTray.SingleInstance`) и он закрывает её перед установкой. Без этого после
  переустановки продолжает работать прежняя копия со старым кодом.
- **После мастера панель перезапускает себя** (`TrayHost.RestartSelf`): панель, которая ставила Node
  и движок, несёт окружение до установки, и сервер с первого раза не поднимается.

## Где что лежит

| Путь | Что это |
|---|---|
| `Program.cs` | точка входа и все ключи командной строки (`--status`, `--server-start`, `--shot`, `--lang-check`, `--env-check`, `--selftest`, `--layout-check`, `--update-prepare`, `--node-check`) |
| `TrayHost.cs` | жизнь в трее: меню, значки, автозапуск, расписания, самопроверка |
| `ServerController.cs` | запуск, остановка и состояние сервера `dsh web` |
| `OnboardingForm.cs` | мастер первой настройки: язык, окружение, порт, рабочая папка, первый запуск |
| `BackupService.cs` / `RestoreService.cs` | копии (тонкая и полная), проверка, накат |
| `UpdateService.cs` | проверка выпусков GitHub, SHA-256, распаковка, сценарий замены |
| `NodeLocator.cs` | где искать Node и движок DSH (включая свой переносимый Node панели) |
| `lang/{ru,en,zh}.json` | все строки интерфейса; ключи обязаны совпадать во всех трёх |
| `tools/` | проверки, сборка раздатки, выпуск |
| `installer/` | Inno Setup 7: установщик со встроенной средой .NET Desktop Runtime 8 |
| `docs/` | `DEVELOPMENT.md` (устройство) и `screenshots/` (снимки для README) |

## Соглашения

- Название продукта — **DSH Panel**, исполняемый файл — `DshTray.exe`, репозиторий —
  `Danerus23/dsh-panel`.
- Языки: русский, английский, китайский. Новая строка интерфейса обязана появиться во всех трёх
  словарях — иначе `check-lang.mjs` не пропустит.
- Комментарии и документация — по-русски, потому что владелец читает их сам.
- Версия живёт в одном месте — `<Version>` в `DshTray.csproj` (панель читает её из сборки),
  история изменений — в `CHANGELOG.md`.
  `installer\build-installer.ps1` пишет `appversion.iss` из версии проекта.
- Лицензия — MIT, автор — `Danerus23`.
