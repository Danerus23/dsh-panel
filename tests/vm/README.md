# Живые прогоны в ВМ (`tests\vm`)

Две проверки класса «живой путь»: они запускают **настоящий установщик** и **настоящую панель**
на чистой Windows в виртуальной машине. Модульные проверки (`dotnet test`) такой путь не заменяют.

Обе работают только с ВМ `DSH-Panel-Test` (Hyper-V, снимок **чистая-ОС**, гость `dshlab`,
вход по **PowerShell Direct**). Снимок применяется в начале и **возвращается** в конце,
машина выключается. На хосте не запускается ничего, кроме самой команды.

> ⚠️ **Пароль гостя в репозитории НЕ ХРАНИТСЯ.** Он передаётся параметром `-GuestPassword` или
> переменной окружения `DSH_VM_GUEST_PASSWORD`; если не задан — проверка отказывается с кодом `2`
> и говорит об этом словами. Имя ВМ и имя гостя (`DSH-Panel-Test`, `dshlab`) — значения по
> умолчанию: это инфраструктура проекта, а не секрет.

> ⚠️ Обе проверки требуют **сумму установщика** и **не начинаются**, если она не сошлась:
> иначе прогон проверял бы не тот файл. Код возврата `2` — отказ до начала.

## 1. `proverka-padeniya.ps1` — падение панели на отказе копии (дефект 2.2.0)

С 2.2.1 панель обязана **выжить**, когда фоновая копия не снялась: отказ уведомления больше
не убивает процесс (дверь `Shell\NotificationDoor.cs`). Проверка ставит именно то состояние,
в котором дефект был возможен: папка копий указывается **внутрь обычного файла**, поэтому копия
по расписанию гарантированно проваливается.

```powershell
$env:DSH_VM_GUEST_PASSWORD = '<пароль гостя>'    # или -GuestPassword, если так удобнее
pwsh -NoProfile -File tests\vm\proverka-padeniya.ps1 `
     -Setup .\upd-build\dist-next\dsh-panel-setup.exe `
     -SetupSum <sha256 установщика>
```

Четыре условия приговора (все обязательны):

1. **сценарий состоялся** — в журнале панели есть строка «автокопия не снята» (иначе «жива»
   ничего не доказывает: падение не было спровоцировано — это ПРОВАЛ, а не «зелено»);
2. **панель выжила** — тот же процесс жив через 25 с;
3. **событий падения нет** — `Application Error` / `.NET Runtime` по `DshPanel` с момента
   запуска — **0**;
4. **новых дампов WER нет** — **0**.

Коды: `0` — «ПРОЙДЕНА», `1` — «НЕ ПРОЙДЕНА», `2` — отказ до начала.
На 2.2.0 проверка дала **код 1** (панель умирала, 2 события падения, 1 дамп) — это и есть
доказательство, что она умеет падать.

## 2. `proverka-kopii.ps1` — десять первых запусков, 0 отказов копии по собственному журналу

Проверка пункта (б) патча 2.2.1: собственный журнал панели (`state\panel.log`) в копию
не попадает, поэтому отказ копии «по своей же блокировке» не появляется ни разу.

```powershell
$env:DSH_VM_GUEST_PASSWORD = '<пароль гостя>'
pwsh -NoProfile -File tests\vm\proverka-kopii.ps1 `
     -Setup .\upd-build\dist-next\dsh-panel-setup.exe `
     -SetupSum <sha256 установщика>
```

По каждому из десяти запусков (профиль каждый раз чистый — копия «первая», как в день установки):
копия **снята** (журнал + архив в папке копий), отказов по причине собственного журнала — **0**,
панель **жива**, событий падения — **0**.

Коды: `0` — «ПРОЙДЕНА», `1` — «НЕ ПРОЙДЕНА», `2` — отказ до начала.
